# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## О проекте

Учебный проект на GNU Octave: численное решение одномерного стационарного уравнения теплопроводности (уравнение Лапласа `d²T/dx² = 0` на стержне длины `L` с граничными условиями I рода) методом конечных разностей и сравнение методов решения получающейся СЛАУ с аналитическим линейным профилем.

Проект состоит из двух равноправных частей:
- `docs/physics.md` — статья на русском (теория, вывод разностной схемы, разбор каждого метода с примерами и алгоритмами);
- `src/` — код, который реализует ровно те методы и формулы, что описаны в статье.

Правки в одной части обычно требуют сверки с другой: формулы, обозначения (`T_L`, `T_R`, `N_x`, `ω`) и критерии остановки в коде должны совпадать со статьёй.

## Запуск

Сборки, тестов и линтера нет. Единственная точка входа — скрипт `src/main.m`. Его нужно запускать **из каталога `src/`**, потому что пути к методам добавляются через `addpath(fullfile(pwd, ...))`:

```sh
cd src && octave --no-gui --eval "main"
```

Скрипт строит график (`figure(1)`) со всеми численными решениями поверх точного `T_exact`. Проверка корректности — совпадение кривых с точным решением (для отдельного метода: `max(abs(T_method - T_exact))`).

## Архитектура кода

- `src/main.m` задаёт физические (`L`, `TL`, `TR`) и сеточные (`nx`) параметры, строит вектор начального приближения `T` (нули внутри, `T(1) = TL`, `T(end) = TR`) и передаёт его каждому решателю.
- `src/methods/direct-methods/` — прямые методы (`gausse.m`, `thomas.m`); `src/methods/iterative-methods/` — итерационные (`jacobi.m`, `gausse_zeidel.m`, `sor.m`).

Общий контракт решателей: функция принимает только вектор-строку температур длины `nx`, берёт граничные значения из первого и последнего элементов и возвращает тот же вектор с заполненными внутренними узлами. Матрица `A` и правая часть `b` **не передаются** — в каждом решателе зашита конкретная система для внутренних узлов (диагонали `1, -2, 1`, правая часть `-TL` / `-TR` в крайних уравнениях). Поэтому смена граничных условий (II/III рода из статьи) или добавление источника потребует правки всех решателей либо изменения их интерфейса.

Особенности текущей реализации:
- `gausse.m` — метод Гаусса, уже специализированный под трёхдиагональную матрицу с единичными внедиагональными элементами (без хранения полной матрицы и без выбора ведущего элемента).
- Итерационные методы используют один и тот же критерий остановки — `max|T^(k+1) - T^(k)| <= 1e-5` при `maxIterations = 10000`; при исчерпании итераций предупреждения нет. В `sor.m` параметр `omega = 1.5` задан константой (в статье приводится формула `ω_opt`).
- Нумерация узлов 1-based и совпадает с индексами Octave: в статье `i = 1..N_x`, в коде `T(1)..T(nx)`.

## Соглашения

- Комментарии в коде и текст статьи — на русском; подписи графиков и легенда — на английском.
- Имена файлов/функций (`gausse`, `gausse_zeidel`, переменная `T_jacoby`) сохраняют исходное написание — не переименовывать без запроса, иначе сломаются вызовы в `main.m`.
- `docs/physics.md` написан в Obsidian-разметке: картинки вставляются как `![[grid-1D.png]]`, формулы — LaTeX в `$...$` / `$$...$$` с `\tag{n}` для нумерации. Новые изображения кладутся в `docs/`.
