# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## О проекте

Учебный проект на GNU Octave: численное решение одномерного стационарного уравнения теплопроводности (уравнение Лапласа `d²T/dx² = 0` на стержне длины `L` с граничными условиями I рода) методом конечных разностей и сравнение методов решения получающейся СЛАУ с аналитическим линейным профилем.

Проект состоит из двух равноправных частей:
- `docs/physics.md` — статья на русском (теория, вывод разностной схемы, разбор каждого метода с примерами и алгоритмами);
- `src/` — код, который реализует ровно те методы и формулы, что описаны в статье.

Правки в одной части обычно требуют сверки с другой: формулы, обозначения (`T_L`, `T_R`, `N_x`, `ω`) и критерии остановки в коде должны совпадать со статьёй.

## Запуск

Сборки, тестов и линтера нет. Единственная точка входа — скрипт `src/main.m`. Его нужно запускать **из каталога `src/`**, потому что пути к методам добавляются через `addpath(fullfile(pwd, ...))`:

```sh
cd src && octave --no-gui --eval "main"
```

Скрипт строит график (`figure(1)`) со всеми численными решениями поверх точного `TExact`. Проверка корректности — совпадение кривых с точным решением (для отдельного метода: `max(abs(TMethod - TExact))`).

## Архитектура кода

- `src/main.m` задаёт физические (`L`, `TL`, `TR`), сеточные (`nx`) и итерационные (`tol`, `maxIterations`, `omega`) параметры, строит вектор начального приближения `T` (нули внутри, `T(1) = TL`, `T(end) = TR`) и передаёт его каждому решателю.
- `src/methods/direct-methods/` — прямые методы (`gauss.m`, `thomas.m`); `src/methods/iterative-methods/` — итерационные (`jacobi.m`, `gauss_seidel.m`, `sor.m`).

Общий контракт решателей: функция принимает вектор-строку температур длины `nx`, берёт граничные значения из первого и последнего элементов и возвращает тот же вектор с заполненными внутренними узлами. Прямые методы вызываются как `T = gauss(T)`, итерационные — как `[T, iter, residual] = jacobi(T, tol, maxIterations)` (так же `gauss_seidel`; у `sor` четвёртый аргумент `omega`). Пропущенный или пустой (`[]`) параметр заменяется значением по умолчанию: `tol = 1e-5`, `maxIterations = 10000`, `omega = 1.5`. `iter` — число выполненных итераций, `residual` — `max|T(i-1) - 2T(i) + T(i+1)|` по внутренним узлам (без деления на `dx²`). Матрица `A` и правая часть `b` **не передаются** — в каждом решателе зашита конкретная система для внутренних узлов (диагонали `1, -2, 1`, правая часть `-TL` / `-TR` в крайних уравнениях). Поэтому смена граничных условий (II/III рода из статьи) или добавление источника потребует правки всех решателей либо изменения их интерфейса.

Особенности текущей реализации:
- `gauss.m` — метод Гаусса, уже специализированный под трёхдиагональную матрицу с единичными внедиагональными элементами (без хранения полной матрицы и без выбора ведущего элемента).
- Итерационные методы используют один и тот же критерий остановки — `max|T^(k+1) - T^(k)| <= tol` (в статье строгое `< ε`); если за `maxIterations` итераций он не выполнен, выдаётся `warning` с последним `max|dT|` и невязкой. `omega = 1.5` задаётся в `main.m` (в статье приводится формула `ω_opt`).
- Нумерация узлов 1-based и совпадает с индексами Octave: в статье `i = 1..N_x`, в коде `T(1)..T(nx)`.

## Соглашения

- Текст статьи — на русском; всё в коде (комментарии, `help`-шапки, тексты `warning`, подписи графиков и легенда) — на английском.
- Имя функции совпадает с именем файла (`gauss`, `gauss_seidel`, `jacobi`, …); при переименовании нужно править и вызовы в `main.m`. Результаты в `main.m` называются `T<Метод>` (`TGauss`, `TJacobi`, `TSeidel`, …).
- `docs/physics.md` написан в Obsidian-разметке: картинки вставляются как `![[grid-1D.png]]`, формулы — LaTeX в `$...$` / `$$...$$` с `\tag{n}` для нумерации. Новые изображения кладутся в `docs/`.
